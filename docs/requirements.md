# 需求 Spec：标的详情页「当日解读」

> 客户端（C 端）需求 Spec。在标的详情页为无投资背景的普通用户提供「用听得懂的话讲清今天发生了什么 + 从哪验证」的当日解读能力。

---

## 1. 背景与目标

### 需求来源

- **用户洞察 + 平台数据**：普通用户从自选/持仓看到当日涨跌后点进详情页想弄清情况，但详情页现有内容为行情走势 + 几十条面向机构读者的研报摘要与快讯，用户看完仍说不出这只标的当天发生了什么。
- **行为调研发现**（需求核心依据）：①用户读到无出处的归因会追问出处、转去搜索引擎自行核对；②多数查看发生在当日涨跌幅不足 1% 的平静日；③平静日常伴随成交量/资金进出的明显变化（量价背离）；④资讯库公告相当一部分发布在收盘后或休市期间；⑤当日涨跌较大的标的中，有一批当天并无可对应的公开消息。

### 目标 App 与现状

- **目标 App**：财富管理 App（手机端，面向普通用户提供股票、指数、基金的行情查看与交易）。
- **现状**：标的详情页 = 行情走势 + 大量机构视角研报摘要/快讯，专业化、碎片化、门槛错配；普通用户难以消化，且对模糊归因不信任而流失到站外。
- **平台数据与能力家底**：已提供行情、净值、成分与持仓、资讯库（公告/快讯/研报摘要，**每条带发布时间与来源**）等接口，也可检索公众平台文章与通用搜索结果；**各接口在不同标的上可返回的数据项并不一致**；可读取用户的关注标的列表；已接入通用大模型能力。这决定了本需求的可行性与边界（详见 §4.3–4.8 规则）。

### 业务目标

1. 让普通用户在**几分钟内看懂**自己关注的标的当天发生了什么。
2. 用**可溯源的解释**把用户"跳出到搜索引擎核对"的流失截留在站内。
3. 提升详情页停留时长、解读点击率、自选/交易转化与次日留存。

---

## 2. 需求价值与量化目标

### 用户价值假设

- 把**价格 + 消息/公告 + 资金流向/成交量异动**三类信号翻译成"一句话结论 + 白话归因"，让无背景用户几分钟看懂；
- 每条归因**带可点击出处**，让用户无需再跳出核对，建立信任与掌控感；
- **平静日给安心确认 + 隐藏信号提示**，**波动日给可信归因**，双场景陪伴。

### 核心指标与量化目标

| 指标 | 现状基线 | 目标 | 数据来源 |
|------|---------|------|---------|
| 详情页停留时长 | 待补充 | 提升 | 内部数据平台 |
| 解读卡片点击/展开率 | 待补充 | 建立基线 | 埋点 |
| 看完解读后跳出到站外核对比例 | 待补充 | 下降（核心价值验证指标） | 埋点 |
| 解读"有用率"投票（正向占比） | 待补充 | 建立基线 | 埋点 |
| 详情页→自选转化率 | 待补充 | 提升 | 内部数据平台 |
| 次日/7日留存 | 待补充 | 提升 | 内部数据平台 |

> 基线需从内部数据平台取数，本阶段标注「待补充」，不阻塞。

## 3. 用户与场景

### 目标用户

- **非专业散户**：主要使用手机端，缺乏金融专业知识，无法自行解读机构级研报或技术图表。
- **被动触发型**：出发点不是主动研究，而是感知波动/日常巡视后想弄清情况，需求是**解释型**而非决策辅助型。
- **高信任门槛**：对模糊解释会追问出处并转搜索引擎核对，需要可溯源、可验证的依据。

### 核心场景

1. **平静日日常巡视**（高频，MVP 重心）：涨跌幅<1% 的交易日，用户点进详情页想确认"我的标的还好吗"；价格没动但资金/量能可能有异动。
2. **波动日有消息**：标的明显涨跌且有可对应公开消息，用户想快速看懂"因为什么"。
3. **波动日无消息**（信任考验）：标的明显涨跌但当天无对应公开消息，用户困惑"为什么动"。

> **用户意图分层**（日常巡视 / 监控等待 / 异动感知 / 主动决策）作为二期由数据驱动的探索方向，不作 MVP 前提。

## 4. 功能需求

### 4.1 当日解读卡片（P0 · 核心）

- **功能描述**：在标的详情页常驻一张「今日解读」卡片，用白话讲清该标的当天发生了什么。同一标的对所有用户展示**通用解读**（一期不做千人千面）。
- **三位一体解读范围**：
  1. **价格**：当日涨跌表现的通俗描述；
  2. **消息/公告**：当日相关消息、公告、研报观点的白话摘要；
  3. **资金/量能**：资金流向、成交量异动的可读解释（低波动日为主角）。
- **业务规则**：
  - **不按波动率门控**——每天点进详情页都要有解读卡片（含平静日）。
  - **诚实归因**：无对应公开消息时，坦白说明"今日无对应公开消息"，并给出可看的资金/板块/大盘线索，不硬凑因果。
  - **强制可溯源**：每条归因结论附可点击出处。
  - **完整信息时间窗**：解读覆盖"上一交易时段收盘至今"，纳入盘后/休市期间发布的公告。
  - **纯解释型**：只解释"发生了什么"，不给"该不该买卖"的决策建议。

### 4.2 量价信号解读（P0 · 差异化护城河）

- **功能描述**：针对平静日（价格几乎不动）但成交量/资金流向出现明显变化的情况，把这类普通用户看不出的隐藏信号翻译成人话（如"今日价格平稳，但主力资金净流出明显，值得留意"）。
- **业务规则**：平静日若检测到量价背离/资金异动，在解读卡片中以"隐藏信号"形式提示；无异动则给"今日平稳无大事，可放心"的安心确认。

### 4.3 归因溯源

- **功能描述**：解读中每条关键结论（消息、公告、数据）挂可点击出处，用户点击可查看原始信息来源。
- **业务规则**：来源不可核实的内容不硬塞归因；全程免责声明、非投资建议、AI 生成明示。
- **信源分级**：**官方信源（公告/快讯/研报摘要，带发布时间与来源）为主归因**；**社区/搜索类信源（公众平台文章、通用搜索结果）降级标注为"网友讨论"、与官方信源隔离展示**，不参与主归因，规避噪音/谣言/合规风险。

### 4.4 数据可用性驱动的优雅降级（P0）

- **功能描述**：平台各接口在不同标的上可返回的数据项并不一致（冷门标的可能缺资金流/研报等）。解读卡片须**按标的实际可用数据项动态组装**。
- **业务规则**：
  - 有则讲、无则不讲：某维度无数据则该维度不展示，不留残缺占位。
  - **明确区分"无异动"与"无数据"**：仅在确有数据且判定平稳时才说"今日平稳无大事"；数据缺失时不得误报"平稳"，避免误导。
  - 不同标的解读的维度组合可不同，但结论表达保持一致风格。

### 4.5 大模型生成约束（P0 · 合规与可信）

- **功能描述**：解读由已接入的通用大模型生成，但须严格约束以保障"可溯源、诚实归因"。
- **业务规则**：
  - AI **只能基于平台给定数据源（行情/净值/成分持仓/资讯库/信源分级后的社区内容）生成解读，禁止自行发挥、编造不存在的消息或归因**。
  - 每条归因须能回指到具体数据源，无支撑的结论不输出。
  - **事实/判断表达约束（传导到 prompt）**：**事实性内容直接陈述；判断性内容必须标注来源与不确定性**（如"有观点认为…（来源：XX）"），禁止把观点包装成"确定句式"的事实陈述。
  - 输出须经合规校验（免责声明、非投资建议），不得出现荐股/买卖建议式表达。

### 4.6 事实 / 判断信息分层（P0 · 可信核心）

- **功能描述**：从数据层到展示层，将信息明确分为「客观事实」与「价值判断」两类，全链路保持区分。
- **业务规则**：
  - **分类以信源类型为主键（确定化，非 LLM 自由判定）**：公告/财务数据/成交量/净值等 → **客观事实**（可直接作为解读依据，可信度高）；公众平台文章/研报解读/市场评论 → **价值判断**（仅作参考佐证，不认定为事实）。
  - **三层区分**：数据层按信源类型打标；解读层事实与判断分别处理；展示层分「事实摘要」与「市场观点」两个模块。
  - **防过度对冲原则**：一句话结论层**锚定在事实上、说人话**，不用限定词淹没结论；判断性内容单独成模块且克制，避免卡片退回"机构式"信息密集难读的老问题。可信 ≠ 啰嗦。

### 4.7 数据处理链路：拉取 → 判定 → 解读（P0 · 三层）

- **功能描述**：数据的拉取、重大性判定、白话解读是三件成本递增的独立事项，分层处理，避免"逢新数据必调大模型"的成本失控。
- **业务规则**：
  1. **拉取层（成本低）**：数据源持续拉取新数据（行情/公告/快讯/文章）并入库保鲜，本层不做任何解读。拉取的技术实现（定时任务打底 / 数据源订阅推送）属研发技术设计，需求层只要求"数据保持新鲜"。
  2. **判定层 triage（成本中低）**：对每批新数据判定"是否重大"，用轻量手段而非完整解读——
     - **结构化信号直接判**：公告自带"类型"字段（停牌/业绩预告/监管处罚等）、行情自带涨跌幅/资金净额数值 → 按阈值规则判定，零 LLM。
     - **自由文本轻量初筛**：快讯/文章等纯文本用关键词/情感极性等轻量方式初筛打标。
  3. **解读层（成本高）**：触发分两类——**每日兜底解读**（收盘后对覆盖标的无条件生成一版，见 §4.8）+ **事件驱动增量重解读**（仅对判定为"重大"的数据盘中即时刷新）。完整白话解读见 §4.5；未过阈值的零碎盘中更新不触发增量重解读，用户看到的仍是上一版（附时间戳），直至下一次兜底或重大事件。

  > **判定与解读是不同量级的处理**：判定"重不重大"看的是数据自带的结构化元信息或轻量分类（廉价），"解读"是把它讲成人话（昂贵）。因此链路是"廉价判定筛一遍 → 只有过关的才昂贵解读"，破解"不解读就无法知道是否重大"的循环。

- **MVP 取舍（偏结构化判定）**：
  - **一期判定层以结构化信号为主**（公告类型字段 + 行情/资金数值阈值），纯文本仅做简单关键词初筛。
  - **取舍代价（明确承认）**：纯文本类"软重大消息"（如仅在公众号/研报文字中出现、无结构化字段标记的利好利空）**可能漏判**，即不能百分百覆盖所有重大事件。
  - **为何接受**：结构化判定确定、可控、可审计、成本低，能快速跑通主链路；且客观事实类重大信号（公告/监管）本就以结构化形式到达，覆盖了绝大多数高价值场景。
  - **二期方向**：对纯文本上更强的文本理解/分类模型，补强"软消息"召回。

### 4.8 时效性与版本感知（P0）

- **功能描述**：解读内容天然具时效性，须让用户知道"看到的是哪个时间点的判断"，并在结论方向性变化时告知。
- **业务规则**：
  - **标注更新时间**：卡片明确显示当前解读的生成/更新时间。
  - **更新机制 = 每日兜底 + 事件驱动增量（两条腿）**：
    - **每日兜底解读（基线，保证平静日不空）**：收盘后对覆盖范围内标的**无条件生成/刷新一版当日解读**——即使当日平静无重大事件，也给出"今日平稳"结论 + 资金/量能状况（呼应 §4.2 平静日为 MVP 重心）。这解决"平静日无事件则无解读"的空窗问题。
    - **事件驱动重解读（增量）**：在每日兜底之上，重大新数据到达时（经 §4.7 判定层）**盘中即时刷新**，不必等收盘；非重大更新不逐条重算，控制 LLM 调用成本。
  - **时段调节**：盘中以行情/资金类信号驱动增量刷新、频率低；休盘期公告/研报/文章集中，走批量处理并产出当日兜底版。
  - **方向性变化提醒（一期做到标的级、应用内标记）**：
    - **判定主体为规则/结构化信号**（与 §4.7 判定层阈值共用同一套规则），**LLM 仅负责把已确认的变化点生成人话文案**，不负责判断"是否报警"。
    - 结论发生方向性变化（如"无明显利空"→"重大利空发布"）时，卡片打上「解读已更新」标记并**高亮变化点**；**所有用户看到一致**（无 per-user 状态），用户下次打开 App 即可见，**不依赖 Push、无需通知权限**。
  - **时间窗过滤**：抓取内容须结合时间戳过滤，剔除观测时效外的旧内容（尤其与当前行情无关的历史讨论），避免噪音引入。
  - **二期方向**：用户级 diff（"自你上次查看后有更新"）+ 可选 Push 主动提醒（需 per-user 状态与通知授权，纳入个性化二期）。

### 4.9 人在回路（HITL）与幻觉控制（P0 · 上线前置）

- **功能描述**：金融解读中一条幻觉即可误导用户决策。采用"纵深防御 + 风险分级路由"控制幻觉，人不审每一条，只审最高风险的少数。
- **业务规则**：
  - **纵深防御（自动，压低幻觉生成概率）**：
    1. **生成前**：强制 grounding——每句归因须回指具体 source；**数值（涨跌幅/资金额等）由规则算好填入，LLM 不改写**，只做白话翻译。
    2. **生成中**：事实走模板槽位、观点走 LLM 但强制标来源与不确定性（承接 §4.6）。
    3. **生成后自动校验 + 自纠错**：溯源校验（挂不上 source 的删）+ 数值一致性校验（对不上原数据拦）+ 合规黑名单（荐股/承诺收益拦）；不过则带反馈重答一次。
  - **风险分级路由（HITL 核心）**：
    - 🟢 **低风险**（平静日"今日平稳"、纯客观事实、校验全过）→ **自动放行**。
    - 🔵 **中风险**（普通归因、含少量观点、中置信度）→ **按比例抽样人审 + 事后复核**。
    - 🔴 **高风险**（重大利空/监管/停牌、结论方向性翻转、低置信/数据稀疏/负反馈聚集）→ **必经人审**。
  - **高风险实时性策略（选定方案 A：稳字优先）**：高风险 AI 主观归因**须待人工复核后才放出**；**人审前先降级——只展示客观事实 + 公告原文链接，不给 AI 主观归因**。理由：重大利空的错误归因危害极大，宁可慢一点先给用户确定的事实，不发未经复核的主观判断。
  - **人的介入点**：上线前建评测集 + 定质量门槛（见 §9 投放门槛）；灰度期高比例/全量人审校准阈值与黑名单；上线后仅审高风险队列；全程用户「有用/没用」投票 + 举报作为分布式 HITL，负反馈聚集自动触发人工复核并下线可疑解读。
  - **错误回流闭环**：人审与用户发现的错误 → 回流为新规则 / 黑名单 / 评测集 case，持续降低同类幻觉。

### 4.10 金融合规风险控制（P0 · 最高优先级红线）

- **功能描述**：在任何情况下不得触碰荐股/引导交易等金融合规红线。核心原则「实质重于形式」——**免责声明无效**（监管明确形式化免责不影响违规定性），合规必须靠内容本身不越界，从产品机制根除。
- **三条法定红线（依据《证券法》《证券投资顾问业务暂行规定》第七/三十二条、《证券、期货投资咨询管理暂行办法》）**：
  - **资质红线**：无证券投资咨询资质，不得提供指向具体证券的投资建议/交易指导/持仓方案。
  - **内容红线**：不给具体标的的买卖时机、价位建议；不承诺/暗示收益（保本、稳赚、晒盈利）；不引导高杠杆。
  - **行为红线**：不代客操作、不诱导频繁交易、不发交易指令、不"抢帽子"。
- **业务规则（多层防线，机制根除）**：
  1. **定位层**：纯解释型产品、非投顾——只解释「已发生的事」（过去时、客观），不预测、不建议、不评价"该不该操作"；连"值得关注""建议留意"等**软引导**也算越界。§8 非目标已永久排除买卖建议。
  2. **生成层**：系统 Prompt 强约束，输出限定为"过去时事实陈述 + 标来源"，禁止未来预测与操作建议句式。
  3. **校验层（硬闸）**：合规词/句式**黑名单 + 合规分类器双检**，命中买卖指向（买入/卖出/加仓/减仓/目标价/止盈止损）、涨跌预测（看涨/看跌/后市/明天会）、收益暗示（稳赚/翻倍/必涨）、软引导（值得关注/建议留意）等 → **硬拦截、不放出，退回重写**。
  4. **信源层**：社区/搜索内容中的他人荐股言论降级为"网友讨论"隔离展示、不进主归因，且同样过合规校验，防止搬运站外违规言论。
  5. **人审 + 用户举报层**：高风险人审含合规复核；用户举报"疑似荐股"即触发下线；错误回流为新黑名单。
  6. **展示层**：常驻免责声明与风险提示，但**明确其为辅助、非合规挡箭牌**——真正合规靠前 5 层。

## 5. 页面与交互旅程

### 5.1 标的详情页 · 当日解读卡片

- **页面用途**：详情页首屏用户理解"今天发生了什么"的核心入口，处于"自选/持仓→详情页"动线的落点。
- **核心元素**：
  - 顶部**一句话结论**（今天怎么了）；
  - 展开区**价格 / 消息 / 资金** 三维归因，每条带出处链接；
  - 平静日的**安心确认 / 隐藏信号提示**；
  - 免责声明与"有用/没用"反馈入口。
- **用户动线**：自选或持仓看到当日涨跌 → 点进详情页 → 走势图附近看到「今日解读」卡片 → 读一句话结论（速懂）→ 需要时展开三维归因/点开出处深挖 → 不再跳出核对。
- **交互与动效**：卡片常驻首屏；归因分维度可展开/收起；出处以可点击链接呈现。
- **关键文案**（待多方案 mock 细化）：结论区如"今天 XX 收平，但资金面有变化"；无消息日如"今日无对应公开消息，波动或与板块/大盘相关"。
- **选定方案**：详情页顶部常驻卡片形态（对比独立 Tab / AI 对话入口后选定，理由：小白无需主动操作即可被动看到，触达最强）。
- **内容结构选定**：金字塔式（一句话结论 → 价格/消息/资金三维 → 每条带出处），直接回应"用户会去搜索引擎核对"的信任诉求。

## 6. 异常与边界处理

| 异常/边界场景 | 触发条件 | 端上表现/兜底方案 | 优先级 |
|--------------|---------|------------------|-------|
| 解读生成失败/超时 | 后端解读未返回 | 降级展示原有行情+快讯，Toast 轻提示，不阻塞页面 | P0 |
| 无任何可用信息 | 无消息、无量价异动（有数据判定平稳） | "今日平稳无大事"安心态文案，不留空白 | P0 |
| 维度数据缺失 | 某接口在该标的无返回 | 该维度不展示；**不得因缺数据误报"平稳"**（区分无异动 vs 无数据） | P0 |
| 无消息但有大波动 | 涨跌大、无对应公开消息 | 诚实说明+资金/板块/大盘线索，不硬凑归因 | P0 |
| 高风险解读待人审 | 重大利空/监管/方向翻转，人工复核未完成 | 先降级只展示客观事实+公告原文链接，不发 AI 主观归因 | P0 |
| 出处链接失效 | 来源不可达 | 隐藏该出处或标注"来源暂不可用"，不误导 | P1 |
| 数据未更新（盘中） | 公告尚未同步 | 标注解读时间戳/更新时间，避免"今天没消息"误判 | P1 |
| 新标的/冷门标的信息稀疏 | 数据源覆盖不足 | 展示已有维度，缺失维度不硬造 | P2 |

## 7. 客户端非功能需求

### 端与机型兼容

- **覆盖端**：iOS + Android 双端（手机端为主，Pad/PC 不在一期）。
- **最低版本**：参照该 App 已上线主要功能的最低版本策略（具体版本号待研发确认）。
- **降级策略**：解读服务不可用或低版本不支持时，降级展示原有行情 + 研报快讯，不影响详情页主体功能。

### 灰度与升级策略

- **发版依赖**：卡片入口若为客户端内嵌需发版；解读内容走服务端下发，内容策略可不发版热更。
- **放量节奏**：灰度（内部/白名单）→ 正式小流量（观测≥3 天）→ 同层大流量 → 回收（≥14 天）。
- **回滚**：功能开关一键关闭，回退到原详情页；金融内容高敏，出现错误归因/合规问题立即降级。

### 实验设计

| 阶段 | 分组 | 流量占比 | 处理（差异点） | 关键假设 |
|------|------|---------|--------------|---------|
| 灰度 | v1 | 0.1%~1% | 内部/白名单体验解读卡片，不进正式实验 | — |
| 正式-小流量 | v0(Control) / v1 | 待实验平台按样本量测算 | 对照（原详情页）vs 开启解读卡片，观测≥3 天 | 开启解读能提升详情页停留时长/自选转化、降低跳出站外核对比例 |
| 正式-大流量 | v0(Control) / v1 | 待实验平台按样本量测算 | 同流量层放量，回收≥14 天 | — |

> 流量占比不默认均分，须由单组最小样本量 ÷ 可用大盘测算；Control 组必填且与实验组同流量层（依据：experiment-design-guide 规范）。

### 埋点设计

| 埋点场景 | 事件 | 关键参数 | 观测目的 |
|---------|------|---------|---------|
| 卡片曝光 | digest_card_show | 标的类型, 波动区间(平静/波动), 有无消息 | 覆盖率、平静日占比 |
| 展开归因 | digest_expand | 展开维度(价格/消息/资金) | 哪类信号最被关注 |
| 点击出处 | digest_source_click | 来源类型 | 可验证性诉求强度 |
| 有用反馈 | digest_feedback | 是否有用, 有无消息 | 诚实归因是否被接受 |
| 后续行为 | （复用交易/自选埋点） | T+1/T+3 交易、加自选、停留时长 | 意图分层假设验证 |

### 开关与权限

- **功能开关**：服务端配置下发，支持按标的类型/用户群/版本分别控制，默认关闭随灰度开启。
- **权限依赖**：无新增端上权限（不涉及定位/通知/相机）；解读依赖已有行情/资讯/资金数据源。
- **内容合规开关**：独立的免责声明/风险提示开关，常开不可关。

## 9. 验收标准

### 当日解读卡片
- [ ] 任意标的、任意交易日（含平静日）点进详情页均能看到当日解读卡片，无空白。
- [ ] 解读包含价格/消息/资金三维中至少已覆盖的维度，一句话结论清晰可懂。
- [ ] 无对应公开消息时，明确诚实说明并给出资金/板块/大盘线索，不出现编造归因。

### 量价信号解读
- [ ] 平静日检测到资金/量能异动时，以隐藏信号形式清晰提示。
- [ ] 平静日无异动时展示安心确认文案。

### 归因溯源
- [ ] 每条关键归因结论附可点击出处；来源失效时不误导。
- [ ] 卡片含免责声明、非投资建议标识、AI 生成明示。

### 数据降级与信源分级
- [ ] 某维度无数据时该维度不展示，且不因缺数据误报"平稳"（区分无异动/无数据）。
- [ ] 官方信源用于主归因；社区/搜索类内容降级标注为"网友讨论"并与官方信源隔离展示。

### 大模型约束
- [ ] 解读内容均可回指到平台给定数据源，无凭空编造的消息或归因。
- [ ] 事实性内容直接陈述、判断性内容标注来源与不确定性，无"观点包装成事实"。
- [ ] 输出无荐股/买卖建议式表达，通过合规校验。

### 事实/判断分层
- [ ] 展示层区分「事实摘要」与「市场观点」两个模块。
- [ ] 一句话结论锚定事实、说人话，未被限定词淹没。

### 时效性与版本感知
- [ ] 卡片明确显示解读生成/更新时间。
- [ ] 重大新数据到达时触发重解读，非重大更新不逐条重算。
- [ ] 结论发生方向性变化时打「解读已更新」标记并高亮变化点，所有用户一致，无需 Push/权限。
- [ ] 抓取内容经时间窗过滤，无时效外历史讨论作为依据。

### 数据处理链路
- [ ] 拉取、判定、解读三层分离；未过阈值的更新只入库不触发完整解读。
- [ ] 判定层以结构化信号（公告类型/数值阈值）为主，判定不依赖完整 LLM 解读。

### 人在回路与幻觉控制
- [ ] 每句归因可回指 source，数值由规则计算、LLM 不改写；自动校验（溯源/数值/合规）全通过才进入分级路由。
- [ ] 低/中/高风险解读按规则正确路由；高风险 AI 主观归因人审前不放出，仅降级展示客观事实+原文链接。
- [ ] 用户负反馈聚集能自动触发人工复核并下线可疑解读。

### 金融合规风险控制
- [ ] 全部输出为"解释已发生"的过去时陈述，无买卖建议/涨跌预测/收益暗示/软引导（含"值得关注"类）。
- [ ] 合规校验硬闸命中违规句式即拦截退回，不放出；免责声明仅作辅助不作唯一合规手段。
- [ ] 社区/搜索中的他人荐股言论被隔离降级，不进入主归因。

## 10. 评测方案与投放门槛

> 回答"解读做得好不好、能不能投放给普通用户"。核心原则：**红线维度一票否决**（合规违规不能被其他高分平均掉），**体验维度分数越高越好**。

### 红线维度（一票否决，不达标绝不投放）

| 维度 | 评测点 | 门槛 |
|------|-------|------|
| **合规安全** | 是否出现荐股/买卖建议/涨跌预测/目标价/收益暗示/软引导；**用诱导性 prompt 对抗测试**（"我该买吗""要不要加仓"）看是否被带偏 | **违规率 = 0**；合规硬闸召回 ≥99.x% |
| **大模型抗幻觉** | 事实准确性、可溯源率、数值一致性（不被 LLM 改写）、事实/判断不混淆 | 幻觉率趋近 0、溯源覆盖 = 100%、无中生有 = 0 |
| **极端与边界** | 无消息大波动是否硬凑、数据缺失是否误报"平稳"、冷门标的、重大利空/停牌是否正确降级、方向反转、脏数据、异常输入、盘中盘后临界 | 极端集关键项零失误、高风险必降级/人审 |

### 体验维度（分数越高越好，决定好不好用）

| 维度 | 评测点 | 核心指标 |
|------|-------|---------|
| **易懂性** | 无背景用户能否读懂、口语化无术语 | **看完能否用一句话正确复述"今天发生了什么"**（金标准） |
| **有用性与信任** | 是否切中关心点、是否消除跳出核对冲动 | 有用率投票、跳出站外核对比例（越低越好）、溯源点击率 |
| **时效与覆盖** | 重大事件更新及时性、每日兜底覆盖、变化提醒准确性、隐藏信号检出质量 | 更新时延、覆盖率、提醒准确率/漏报率 |
| **工程与成本** | 端到端时延、判定层过滤有效性、单次成本、降级成功率 | P95 时延、成本/条、降级兜底成功率 |

### 评测方法（三种组合）

1. **离线评测集（主力）**：人工标注黄金评测集，覆盖各场景 + 专门的**对抗集/极端集/合规攻击集**，可自动化回归，每次迭代必跑。
2. **人工专家评审**：金融+合规专家对抽样解读打分，覆盖 LLM 自动判不准的灰色地带。
3. **真人测试 + 灰度线上**：小白可用性测试（能否复述）+ 灰度 A/B 看真实行为（停留/跳出/留存/举报率）。

### 投放门槛（达到什么水平才能给普通用户）

- **硬门槛**：合规违规率 = 0、幻觉率趋近 0、溯源覆盖 = 100%、极端集关键项零失误、高风险必降级/人审——**任一不达标即禁止投放，无商量余地**。
- **体验门槛**：易懂性（小白复述正确率）、有用率、跳出核对比例等达预设基线，且灰度期无重大负反馈聚集。
- **放量路径**：红线全过 → 内部/白名单 → 灰度小流量（高比例人审）→ 各项稳定达标 → 逐步扩量至全量；**任一阶段红线指标反弹立即回滚**。
