# 运转方式说明：一次解读从产生到呈现的完整过程

> 本文档说明一条「当日解读」从平台数据到呈现给用户的完整运转过程，并讲清**大模型与人/规则各自承担什么**。可脱离其他材料单独阅读。

## 一、总览：三阶段、五参与者

一次解读的运转横跨五个参与者——**用户、前端（详情页）、规则/系统层、大模型层、数据源/人工**，分三个阶段流转：

```
【后台数据处理】拉取 → 判定 → 组织 → 生成
        ↓
【合规硬闸 + 人在回路】校验 → 分级 → 版本判定
        ↓
【前台呈现与反馈】下发 → 阅读 → 反馈（回流优化）
```

---

## 二、逐环节说明

### 阶段一 · 后台数据处理（用户无感，持续运行）

**① 拉取入库（规则/系统）**
数据源持续拉取新数据（行情/公告/快讯/资金，每条带发布时间与来源）并入库保鲜，本层不做任何解读。拉取的技术实现（定时任务打底 / 数据源订阅推送）属工程实现，产品层只要求"数据保持新鲜"。

**② 判定 triage：是否"重大"（规则/系统，非大模型）**
对每批新数据用**轻量手段**判定是否重大——公告自带的"类型"字段（停牌/业绩预告/监管处罚）、行情自带的涨跌幅/资金净额数值，按阈值规则判定，**不需要完整解读**。这一步破解了"不解读怎么知道是否重大"的循环：判定看的是数据自带的结构化元信息（廉价），解读是把它讲成人话（昂贵），两者不是一回事。
- 未过阈值 → 仅入库，不触发增量解读，等收盘每日兜底；
- 判定重大 → 盘中即时进入解读流程。

**③ 上下文组织（规则/系统）**
按信源类型给数据打「事实/判断」标签、按时间窗过滤去噪、按标的实际可用数据动态组装（有则讲、无则不讲）。

**④ 生成白话解读（大模型）**
大模型基于给定数据生成：一句话结论 + 价格/消息/资金三维归因 + 平静日隐藏信号。**关键约束**：数值由规则算好填入、大模型不改写；大模型只做"翻译"，事实直陈、观点标来源，禁止编造。

### 阶段二 · 合规硬闸 + 人在回路（放行前必经）

**⑤ 校验（规则硬闸）**
溯源校验（挂不上来源的删）+ 数值一致性校验（对不上原数据拦）+ **合规黑名单校验**（荐股/买卖建议/收益暗示拦）。不通过则带反馈重写一次。

**⑥ 风险分级路由（规则 + 人工）**
- 🟢 低风险（平静日"今日平稳"、纯客观事实）→ 自动放行；
- 🔵 中风险（普通归因、含少量观点）→ 抽样人审；
- 🔴 高风险（重大利空/监管/停牌、方向性反转、低置信）→ **必经人工复核**；人审前先降级只展示客观事实 + 公告原文链接，不发大模型主观归因。

**⑦ 版本感知（规则判定 + 大模型写文案）**
方向性变化由**规则判定**（是否算重大变化、是否报警），命中则打「解读已更新」高亮标记；**大模型只负责把变化点写成人话**。

### 阶段三 · 前台呈现与反馈

**⑧ 下发（前端）**：详情页顶部常驻「今日解读」卡片，显示更新时间戳。
**⑨ 阅读（用户）**：读一句话结论（速懂）→ 展开三维归因 → 点出处溯源（不跳出核对）。
**⑩ 反馈（用户 → 规则）**：「有用/没用」投票 + 举报疑似荐股 → 负反馈聚集自动触发人审/下线 → **错误回流为新规则/黑名单/评测集**，形成闭环。

---

## 三、核心：大模型与人/规则的分工

| 环节 | 承担者 | 做什么 |
|------|--------|--------|
| ② 判定是否重大 | **规则** | 结构化信号 + 阈值，非大模型 |
| ④ 生成解读文案 | **大模型** | 只做"翻译/表达" |
| ⑤ 合规/溯源/数值校验 | **规则硬闸** | 违规即拦截 |
| ⑥ 是否放行 | **规则 + 人工** | 分级路由，高风险必经人审 |
| ⑦ 是否报警（方向变化） | **规则判定** | 大模型只写文案 |
| ⑨ 最终是否采信 | **用户** | 自主判断 |

> **一句话总结**：大模型只出现在「表达/翻译」位（④⑦），所有"判断"——是否重大、是否合规、是否放行、是否报警——都交给确定性的规则与人。**把最会幻觉的组件放在最安全的翻译位，是这个产品可信、可控、合规的根基。**
